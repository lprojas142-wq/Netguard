PASO 2. INSTALAR PYTHON
------------------------------------------------------------------------------

1. Entra a https://www.python.org/downloads/ y descarga Python 3 (3.8 o más
   nuevo; recomendado 3.11 o superior).
2. En el instalador de Windows MARCA la casilla "Add python.exe to PATH" y da
   "Install Now".
3. Comprueba en una terminal:
       python --version
   Si no lo reconoce, prueba:
       py --version
   (en ese caso usa "py" en lugar de "python" en todos los comandos).

No necesitas instalar nada más: la biblioteca PLY ya está dentro de la
carpeta ply/. (Si de todos modos quieres instalarla: pip install ply==3.11)

PASO 3B. ABRIR Y EJECUTAR DESDE VISUAL STUDIO CODE
------------------------------------------------------------------------------

Una sola vez:
  1. Instala VS Code (https://code.visualstudio.com) y Python (Paso 2).
  2. Descomprime NetGuard_Proyecto.zip (clic derecho > Extraer todo).
     No lo abras desde dentro del .zip.
  3. En VS Code: Archivo > Abrir carpeta... > elige la carpeta NetGuard
     (la que contiene netguard.py). Si pregunta "¿Confía en los autores?",
     elige "Sí, confío".
  4. Abajo a la derecha te ofrecerá instalar la extensión "Python" de
     Microsoft: dale Instalar. (O ve a Extensiones, Ctrl+Shift+X, y busca
     "Python".)
  5. Elige el intérprete: Ctrl+Shift+P > escribe "Python: Select Interpreter"
     > elige el Python 3 que instalaste.

FORMA 1 · Con F5 (la más cómoda)
  La carpeta ya trae configuraciones listas (.vscode/launch.json).
  1. Abre el panel "Ejecutar y depurar" (Ctrl+Shift+D, o el ícono de ▶ con
     un bichito en la barra izquierda).
  2. Arriba, en la lista desplegable, elige una opción:
       1. NetGuard: ejecutar reglas.ng
       2. NetGuard: presentación (todas las fases con pausas)
       3. NetGuard: ejecutar el archivo .ng que tengo abierto
       4. NetGuard: todas las fases del .ng abierto (--todo)
       5. NetGuard: optimización y comparación
       6. NetGuard: mostrar errores (varios_errores.ng)
       7. NetGuard: pruebas automáticas (41 pruebas)
  3. Presiona F5 (o el botón ▶ verde). La salida aparece en la TERMINAL de
     abajo. En la opción 2 presiona Enter en la terminal para avanzar.
  Las opciones 3 y 4 usan el archivo que tengas abierto en el editor:
  abre primero un .ng (por ejemplo ejemplos/puertos.ng) y luego F5.

FORMA 2 · Escribiendo los comandos en la terminal de VS Code
  1. Terminal > Nueva terminal (o Ctrl+ñ / Ctrl+`).
  2. La terminal ya se abre en la carpeta NetGuard. Escribe, por ejemplo:
         python netguard.py ejemplos/reglas.ng
         python netguard.py ejemplos/reglas.ng --tabla --cuadruplos
         python pruebas.py
     (si "python" no funciona, usa "py")
  Todos los comandos de los Pasos 4 a 10 funcionan igual aquí.

FORMA 3 · Botón ▶ "Run Python File"
  Abre netguard.py y presiona el ▶ de arriba a la derecha: NO sirve solo,
  porque netguard.py necesita que le digas qué programa .ng ejecutar.
  Usa la Forma 1 o la 2. (Con pruebas.py el botón ▶ sí funciona.)

Para editar las reglas: abre ejemplos/reglas.ng, cambia por ejemplo
"maxAttempts : int = 5" por 10, guarda (Ctrl+S) y vuelve a presionar F5.

Si la consola muestra caracteres raros (Ã³), escribe en la terminal:
    chcp 65001
y vuelve a ejecutar.

PASO 8. ESCRIBIR TUS PROPIAS REGLAS
------------------------------------------------------------------------------

1. Crea un archivo de texto con extensión .ng (por ejemplo mis_reglas.ng) en
   la carpeta ejemplos. Usa el Bloc de notas o VS Code, guardado en UTF-8.
2. Estructura obligatoria, en este orden:
       LIMIT ...        (0 o más umbrales globales)
       LOAD EVENTS FROM "archivo.log" AS nombre   (1 o más)
       sentencias       (FOR EACH, IF, LET, asignaciones, ALERT, MARK)
3. Reglas rápidas:
   * Palabras reservadas en MAYÚSCULAS; tipos y true/false en minúsculas.
   * Cada IF y cada FOR EACH cierra con END.
   * Comentarios con #.
   * Campos de event: sourceIP, eventType, port, failedAttempts, trafficMB, status.
4. Ejecuta:  python netguard.py ejemplos/mis_reglas.ng

Formato del .log (primera línea opcional de encabezado):
    sourceIP,eventType,port,failedAttempts,trafficMB,status
    192.168.1.10,login_failed,22,7,1.2,pendiente

Idea para la demo en vivo: pide a la profesora un umbral (por ejemplo
"maxAttempts = 10") y cámbialo en el programa frente a ella.

PASO 9. CÓMO FUNCIONA EL CÓDIGO POR DENTRO
------------------------------------------------------------------------------

Flujo (netguard.py):
  1. Lee el .ng
  2. compilar(): lexer → parser (con semántica, tabla de símbolos y codegen)
  3. Si hay errores: los imprime y NO ejecuta
  4. optimizar(): mejora las cuádruplas
  5. MaquinaVirtual.ejecutar(): corre las cuádruplas sobre el .log
  6. Escribe reporte.txt

lexer.py (PLY lex)
  Cada token es una expresión regular. Ej.: t_ID = [a-zA-Z_][a-zA-Z0-9_]*.
  Las palabras reservadas se buscan en un diccionario después de reconocer un
  ID. IP_LIT se revisa antes que FLOAT_LIT para que 192.168.1.10 no se lea
  como 192.168 + .1 + .10.

parser.py (PLY yacc, LALR(1))
  Cada función p_algo tiene en su docstring la producción de la gramática y
  en su cuerpo la REGLA SEMÁNTICA. Ejemplo:
      def p_decl_local(p):
          "decl_local : LET ID ':' tipo '=' expr"
          ... revisa S02 y S03, inserta en la tabla, genera (=, valor, —, ID)
  PLY construye la tabla LALR (122 estados, 0 conflictos) y llama a cada
  función cuando REDUCE esa producción, es decir, en postorden.
  Los no terminales "marcadores" (op_suma, op_mult, encabezado_if,
  encabezado_else, encabezado_for…) sirven para ejecutar una acción en el
  momento exacto: apilar un operador apenas se lee, o generar el GOTOF justo
  después de la condición del IF (acciones #1 a #5 de la sección 8.3).

semantic.py
  resultado(op, t1, t2) = la tabla de compatibilidad 8.2.
  PilaSemantica tiene POper, PTipos, POptr y PSaltos; operacion_binaria()
  saca el operador y dos operandos, revisa tipos, pide un temporal y genera
  la cuádrupla. Guarda la traza que se ve con --traza.

symtable.py
  Pila de diccionarios (tablas hash), uno por ámbito. buscar() recorre del
  tope al fondo. Asigna direcciones: 1000 globales, 2000 locales,
  3000 temporales, 4000 constantes, 5000 colecciones.

codegen.py
  Lista de cuádruplas numeradas desde 1. rellenar() hace el backpatching de
  los saltos. a_tripletas() convierte a tripletas.

optimizer.py
  Repite las pasadas hasta que nada cambia: plegado y propagación de
  constantes, simplificación algebraica, subexpresiones comunes, código
  muerto, salto a salto, código inalcanzable; además reducción de fuerza y
  movimiento de código invariante. Al final renumera y corrige los saltos.

vm.py
  Ejecuta cuádrupla por cuádrupla con un contador de programa (pc). La
  memoria es un diccionario {dirección: valor}. FE_INIT/FE_NEXT recorren la
  lista de eventos; ALERT y MARK escriben el reporte.

ANEXO A. DIFERENCIAS CON EL DOCUMENTO (PARA CONTESTAR SI PREGUNTAN)
------------------------------------------------------------------------------

1. La gramática del código tiene no terminales "marcadores" extra
   (op_suma, encabezado_if, etc.). Aceptan EXACTAMENTE el mismo lenguaje que
   la gramática 7.3; solo sirven para ejecutar las acciones #1-#5 y apilar
   operadores en el momento correcto.
2. En la traza, la columna "Símbolo" muestra el token que el parser estaba
   leyendo (lookahead) cuando hizo la acción. En un parser ascendente el
   operador se saca al ver el siguiente token, por eso a veces aparece IF,
   ALERT o la variable de la siguiente línea en lugar de "fin".
3. En riesgo.ng los temporales empiezan en t2 porque t1 lo usa FE_NEXT del
   ciclo; en el documento la expresión aparecía sola.
4. El optimizador tiene dos técnicas pequeñas adicionales: "salto al
   siguiente" (GOTO a la instrucción que sigue) y plegado de GOTOF con
   condición constante.
5. La propagación de constantes también se aplica a un LET que se asigna una
   sola vez (además de los LIMIT).
6. Limitación conocida: no se elimina una asignación que se sobrescribe antes
   de leerse (por ejemplo LET riesgo = 0.0 seguido de riesgo = ...). Para eso
   haría falta análisis de variables vivas; queda como mejora.
7. Códigos de error agregados al diseño: L01, L02 (léxicos), P01, P02
   (sintácticos) y R01, R02, R03 (ejecución). Los S01-S09 son los del
   documento.

ANEXO B. PROBLEMAS COMUNES
------------------------------------------------------------------------------

"python no se reconoce como un comando"
    → Usa py en lugar de python, o reinstala Python marcando "Add to PATH".

Se ven caracteres raros (Ã³ en lugar de ó) en la consola de Windows
    → Ejecuta primero:  chcp 65001
      (demo.bat y pruebas.bat ya lo hacen) o usa Windows Terminal / VS Code.

[R01] no se encontró el archivo de registro
    → La ruta del LOAD es relativa a la carpeta del .ng. Revisa el nombre o
      pásalo como segundo argumento.

[P01] token inesperado 'END'
    → Casi siempre falta algo antes: una comilla, un FROM en ALERT o un AS en
      MARK. Revisa la línea anterior.

Las tablas se ven cortadas
    → Maximiza la ventana o guarda la salida en archivo:  ... > salida.txt
